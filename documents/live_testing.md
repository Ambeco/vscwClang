# Live testing on vscode.dev

How to drive the real vscode.dev with a persistent test browser, plus the findings from the first full pass
(2026-10-21) with enough context for another session to pick each one up. Fixed items are listed so they are not
re-investigated.

## Harness

- **Chrome with a dedicated profile**, never the user's: `chrome.exe --user-data-dir=%USERPROFILE%\.claude\chrome-test-profile --remote-debugging-port=9333 --no-first-run https://vscode.dev/`. Chrome 136+ refuses remote debugging on its default user-data dir, so `--profile-directory` alone cannot be automated. The profile keeps the granted permissions, the installed extension, the `vscwclang.toolchainUrl` user setting and the cached toolchain (listed in `~/.claude/temp-cache-registry.md`, keep).
- **Extension**: `npm run package-web`, `npx serve --cors -l 5000`, then palette "Developer: Install Extension from Location..." with `http://localhost:5000` (a trust popup and a "read local files" popup appear once; reinstall after a `package.json` change, reload the tab after code changes).
- **Local toolchain**: `node scripts/serve-dist.cjs llvm-artifacts/mtdist` (adds the CORP header COEP needs; `--slow` throttles so the Cancel button can be clicked), and user setting `{"vscwclang.toolchainUrl": "http://localhost:5001"}` (open it with palette "Preferences: Open User Settings (JSON)"; type it with `insertText`, because typing triggers bracket auto-close). The output channel says `toolchain override ... accepted without a pin`.
- **Driver**: `node scripts/live-driver.cjs`, then `curl --data-binary @test.js http://127.0.0.1:9444/run`. `seed({...files})` writes an OPFS folder, reloads and opens it through a patched `showDirectoryPicker` (no picker click, no GitHub sign-in; `vscode.dev/github/...` demands a GitHub login). `cmd('vscwClang: Build C++')` clicks the exact palette row (typing the name and pressing Enter picks the "recently used" command instead). `console.log` collects console warnings/errors, failed requests and HTTP >= 400 per `step()`.
- **Debug**: F5 picks "C++ in browser" from a debugger picker the first time; breakpoints persist across `seed()` (run the palette's `Remove All Breakpoints` first); toggle one with palette "Go to Line/Column..." then `cmd('Debug: Toggle Breakpoint')`, and continue with `.debug-toolbar .codicon-debug-continue`. Program output is in the `vscwClang debug: <name>` terminal unless `console` is `internalConsole`; read the Debug Console with `document.querySelector('.repl').innerText`.
- **Gotchas**: this opens an *untitled multi-root workspace* (`default.code-workspace`, folder `file:///proj`); workspace settings live in that file (palette "Preferences: Open Workspace Settings (JSON)"; keep `folders` when replacing it) and persist across `seed()`, so reset them between tests. F11/Shift+F11 never reach VS Code (Chrome fullscreen); click the debug toolbar instead. The terminal needs a click before it takes typed input. `Terminal` panel text is canvas, so read run output from screenshots. `p.locator(...).innerText()` waits for the default timeout when the element is missing; use `p.evaluate` for polling. Backslashes in heredoc-written JS arrive halved (write test files with the Write tool).
- **Driver gotchas (2026-11-08)**: `seed()` already opens the folder, so do not `p.reload()` after it (the folder is lost); the extension activates only when a C/C++ file is open or a command runs (double-click `main.cpp` first); a `curl --max-time` that expires does not stop the script, which keeps driving the page, so never start a second script while one runs; `Clear downloaded toolchain` leaves the clangd index shards (`clangd-cache`), so a re-index is warm; the Output panel has a filter box (`getByPlaceholder(/Filter/)`) to grep a long channel; a backslash-n escape inside the C++ source of a test script arrives as a real newline when the script is written by heredoc (the build then fails), so write such scripts with the Write tool.
- **Driver gotchas (2026-11-08, second pass)**: open files with Ctrl+P and the path (tree clicks are brittle); click `.monaco-modal-editor-block .view-lines` to type into the User Settings (JSON) modal (a bare `.monaco-editor` matches the output editor first), and rewrite the whole file with Ctrl+A + `insertText`, since an earlier session left it malformed; the Output filter box often does not narrow the text, so judge clangd behaviour from Problems or the editor instead; with no `toolchainUrl` override the pinned v24.0.13 downloads from jsDelivr by itself. Run scripts from `$LOCALAPPDATA/Temp` (Git Bash `/tmp` is not Node's `C:\tmp`).
- **Logging level and hung pages (2026-11-16)**: the test profile's user settings (IndexedDB `vscode-web-db`, store `vscode-userdata-store`, key `/User/settings.json`) set `vscwclang.loggingLevel` to `Debug`, which made clangd verbose and froze the page on a 1.8 MB document before the output fixes; the default is `Error`. A folder-level `.vscode/settings.json` value did not override the user value in the live run, so change the user setting (put the file's bytes in IndexedDB, then reload). A hung page (`p.evaluate` never returns) is unrecoverable: kill the Chrome with port 9333 and restart it and `live-driver.cjs` (the driver dies with its Chrome). `log('x', ...)` in a script writes at once, unlike the script's return value, so use it for progress; `console.warn` lines from the extension host reach the driver's `console.log` live.
- **Ignorable console noise** (vscode.dev itself): `[lifecycle] Long running operations during shutdown`, `IndexedDB database 'vscode-web-db' is closed`, `Failed to execute 'abort' on 'IDBTransaction'` and `Unable to resolve resource output:tasks` (all caused by the harness reloading the page), `extension 'github.vscode-pull-request-github' wants API proposal`, `[AgentHost:remote]`, `Permissions policy violation: unload`, `[CloudSandboxApi] No 'github' session`.

## Fixed during the pass

- `vscwclang.compileCommands.include` nested under the string setting `vscwclang.compileCommands`: VS Code ignored it (console: `Ignoring vscwclang.compileCommands.include as vscwclang.compileCommands is ""`) and `get()` returned `""`, so Build and Run threw `...get(...).map is not a function` whenever a `compile_commands.json` existed. Renamed to `vscwclang.compileCommandsInclude`; `settingsSchema.node.test.ts` fails on any setting key that is a dotted prefix of another. Verified live afterwards.
- The flag error for `--target`/`-march` suggested a `threads` setting that does not exist; it now says "to remove it".
- Go to Definition into `/sysroot`/`/resource` headers failed with "The editor could not be opened": they now open through a read-only `vscwclang-toolchain:` file system (`toolchainFileSystem.ts`); clangd's percent-encoded URIs are decoded (`c%2B%2B`).
- Duplicate Problems (build and clangd): `publishDiagnostics` skips a build diagnostic that clangd already shows on the same line with the same text (`isSameReport`). Not covered: the task problem matcher, whose markers cannot be filtered, and clangd publishing after the build ran.
- The terminal now takes focus after Run (`show(false)`).
- Run of a `-g` task hung with a blank terminal (the linked debug stub waits for a debugger host): fixed in `fd6aa27`, Run always builds in release mode. Not re-verified live.

## Open findings (most important first)

2. **clangd is very slow to become useful, and after every edit. Working as intended until V2 multithreading (decided 2026-10-21): do not optimize; revisit only after the custom runner lands.** `main.cpp` including `<iostream>`, `"model.h"` (`<map>`, `<string>`, `<vector>`): first preamble took 64 s (clangd log `Building first preamble` at 23:11:21, `indexed preamble AST` at 23:12:25), first hover about 113 s after opening the file, and after typing `m.` completion replied after about 50 s (179 ms of its own work, so it queued behind a preamble rebuild) and diagnostics after about 50 s. The same pass with only `<cstdio>` showed diagnostics after 4 s and the whole 6-file index in 6 s, so cost scales with the libc++ headers in the preamble although `clang.wasm` compiles the same `main.cpp` in 1.4 s. While it is busy hover and completion show "Loading..." with no progress indication (no status bar item before indexing starts). `-sync` mode serializes everything behind it. Debug logging was not the cause (default logging: 113 s). Hypotheses to check: preamble `.pch` writes go to `/tmp` which is `vscodeFileSystem` on `globalStorageUri` (slow IndexedDB-backed writes; try a memory file system for `/tmp`), clock/IO cost under `wasm-wasi-core`, or preamble rebuilds on every edit (`Built preamble Version 1 for version 7` was logged after an edit to line 8 only). Also logged on every request: `E VFS: failed to set CWD to /workspace: Link has been severed`. Repro: `vscwclang.loggingLevel: "Debug"` in user settings, open the project, read the `vscwclang` output (filter `E[`, `preamble`, `reply:`).
3. **Tasks UI runs nothing: a web-workbench limit, not our provider (root cause found 2026-10-22).** `Tasks: Run Build Task`, Ctrl+Shift+B and `Tasks: Run Task` return at once because the workbench's task service never sets `_tasksReconnected`: it waits for the terminal service to connect a backend (`_initializePrimaryBackend` stalls in `getBackend`), which a web workbench with no pty host never does. Reproduced under `npm test` (test-web) with a `tasks.json` default build task: our `resolveTask` is called, but nothing starts and nothing is logged. The workbench commands are no-ops for every task there; `tasks.executeTask` and Configure Default Build Task still work. Decided not to override Ctrl+Shift+B (we mirror cpptools' keys only where web leaves them free); use the `vscwClang: Build C++` command, which honours the default `tasks.json` build task.
4. **`C_Cpp.*` fallback settings were ignored on vscode.dev (fixed in code 2026-10-22, re-verify live).** Workspace-level settings of keys no extension registers are dropped, so package.json now contributes the `C_Cpp.default.*`, `files.exclude`, `loggingLevel` and `intelliSenseEngine` keys we read (test `C_Cpp.default.* fallbacks are read from a registered, resource-scoped setting`).
5. **Folder-level `.vscode/settings.json` was not applied for `vscwclang.flags` in a multi-root workspace (fixed in code 2026-10-22, re-verify live).** The per-project `vscwclang.*` settings are now `"scope": "resource"` and read with the folder uri (`projectSettings`). Still unknown: whether a real vscode.dev "Open Folder" opens as multi-root. Activation now logs `[vscwclang] workspace: ...` in the `vscwclang` output channel; open a real local folder and read it.
6. **`RuntimeError: unreachable` is logged to the console by `wasm-wasi-core` (`mainWorker.js:3452`, `MainBrowserHostConnection.handleMessage`) during every build**, in a wasm function of a 87k-function module (clang; offsets `0x1a81918`), even when all steps exit 0. A failed build logs a different one (172,717-function module, `0x381209d`, then `vscwClang: build failed (exit 1)`). Probably the `proc_exit` unwind, so cosmetic, but it should be confirmed that no compile output is lost.
7. **Program traps still hang the terminal** (known, README): out-of-bounds access, divide by zero and an uncaught `throw` print only `RuntimeError: ...` / `Exception` in the browser console while the terminal stays on the last output until Ctrl+C. `try`/`catch` works with the local `v24.0.2` (eh build); the pinned `v24.0.1` still passes `-fno-exceptions` (its `compile-flags.json`), so the README line "No C++ exceptions" is right until `v24.0.2` is pinned, then it must change.
8. **Smaller UX**: Debug call stack names the entry frame `__original_main` instead of `main`; the Variables pane shows `(locals not listed)` (known); step over from inside `sq` returns to the caller's loop line instead of the next line of `sq` (block-granular, known); Anycode (built in) provides inlay hints, breadcrumbs `anycode > main` and `#include` links alongside clangd, so duplicate symbol results are possible (not observed for hover/definition).

New findings:

2. Harness: Ctrl+G does not reach VS Code (use the palette "Go to Line"), and the command label is `Build and Run C++ with Arguments...`.
- **Cold-index timing recipe (2026-11-08)**: delete IndexedDB `vscode-web-db` / `vscode-userdata-store` keys containing `/clangd-cache/`, `seed()` the project (sources plus a `compile_commands.json` carrying the toolchain flags), open one source with Ctrl+P, poll `.part.statusbar` for `indexing N/M`. - **Harness gotchas (2026-11-10)**: `ctx.grantPermissions(...)` replaces the profile's stored permissions for the origin, including the one that lets vscode.dev fetch `http://localhost:5000` (the extension then fails with `net::ERR_FAILED` and nothing activates); run `ctx.clearPermissions()` right after.
