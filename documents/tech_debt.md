- `toolchain/toolchain.ts` `build()`: one ~240-line function (compile pool, cache, PCH, link, diagnostics); plus module-level mutable state (`objectCache`, `lastLinks`, `shimObjects`, `loadedPch`, `modules`, `stores`) makes it untestable without the browser suite; split into pool/cache/link units and inject state.
- `toolchain/toolchain.ts`: also holds the IntelliSense-settle promise (`settleIntelliSense`/`whenIntelliSenseSettled`, global resolve-from-outside), `getModule`, and store registry; unrelated to building, move out.
- `extension.ts` `runMakeCommand`: `tool: 'make' | 'ninja'` flag branches two different planners and owns module-level `makePack`; use a planner interface (`plan(): Promise<{cancelled, build?}>`) with one command registration per tool.
- `make/ninjaBuild.ts` `ninjaBuildOptions`: ~60 lines mixing dir discovery, include preload, host-root inference, goal choice, program picker, lowering; stray bare `{ ... }` block; the program-picker and lower/notes tail duplicate `make/makeBuild.ts` `makeBuildOptions` (extract shared `pickAndLower`).
- `make/makeBuild.ts` `buildOptionsFromLowered` is imported by `ninjaBuild.ts`; it belongs with `buildgraph/lower.ts` (Ninja depends on the Make file).
- `buildgraph/*` plan results `{ cancelled: boolean; build?: BuildOptions }` repeated inline in `extension.ts`, `projectConfig.ts`, `makeBuild.ts`, `ninjaBuild.ts`; extract a named `PlanResult` type (cancelled+build is an unchecked pair).
- `buildgraph/graph.ts`, `classify.ts`, `lower.ts`: paths, goals and programs are plain `string` (guest vs host vs workspace-relative paths mixed; `/workspace/` prefix stripped ad hoc in `makeBuild.ts` and `ninjaBuild.ts`); add branded path types.
- `projectConfig.ts`: module-level `lastCppFile`; `chooseRun`/`chooseCompileDatabase` mix UI (QuickPick) with plan selection and take `(context, folder, log)` triples everywhere; the same `context, log, diagnostics` trio is threaded through all of `extension.ts`.
- `extension.ts` `buildAndRun`/`debugPlan`/`runMakeCommand`: `buildWorkspace` + `publishDiagnostics` + `reportBuild` sequence copy-pasted three times; fold into one helper.
- `toolchain/projectModel.ts` (431 lines): task/launch parsing, variable resolution, arg mapping, compile-database planning and host-root inference in one file; `inferHostRoot(db: unknown, ...)` and `planFromCompileCommands(db: unknown, ...)` take untyped input.
- `host/wasiGuest.ts` (567 lines) is the WASI implementation plus fs/error types in one file; `FsErrno` string-union errors and `GuestResult`/`GuestOptions` live beside the 400-line class.
- Tests: `*.node.test.ts` cover buildgraph in isolation, but the Make/Ninja command path (`extension.ts` to `buildWorkspace`) has few browser tests and no Ninja browser test; slow (visible Chromium, port 3000) and flaky on a stale server.
- `scripts/build-make-wasm.mjs` + `scripts/make-wasm/gl/*`: hand-written gnulib stand-ins and source patches (`dir.c` sizeof, `main` params) with no check that they still apply to a new make version.
